# 代码评审 Checklist

对照实现代码、测试、`evidence/` 日志与已批准的计划(plan.md 或 spec.md + design.md)逐条检查。**评审者必须自己重跑测试、自己读完整 git diff,不采信作者叙述。** 加载的 `ext-*` 扩展若声明了本层追加检查项,一并检查。

## 证据链

- [ ] 评审者本人重跑全量测试套件且通过(自己运行,结果写入 findings 依据)
- [ ] 每个任务在 evidence/ 有 red 与 green 日志;抽查 red 日志,失败原因是行为缺失而非编译/拼写错误
- [ ] evidence/ 日志由 hf_gate.py run 产生(有标准头尾行),无手工编辑痕迹
- [ ] git diff 改动面与任务清单一致,无范围蔓延;有则必须已向用户说明
- [ ] frame 风险档位与实际 diff 相符(档位 1 的 diff 却碰了数据/安全/公共接口 → 严重 finding)

## 测试质量

- [ ] 测试验证的是行为(输入→可观察输出),不是实现细节(私有函数、内部调用次序)
- [ ] 覆盖边界值与失败路径,不只有 happy path
- [ ] 无造假测试:断言恒真、断言被注释、为通过而放宽断言、测试里复刻实现逻辑
- [ ] mock 只用于真正的外部边界(网络、时钟、文件系统),没有 mock 被测对象本身

## 计划符合度

- [ ] 实现遵循计划的模块划分、依赖方向与接口契约;偏离处有记录与理由
- [ ] 错误处理与计划声明的失败模式一致,没有静默吞错

## 代码质量

- [ ] 命名清晰;无复制粘贴式重复;无死代码、被注释掉的代码、调试残留
- [ ] 没有引入计划未声明的新抽象层
- [ ] 遵循项目既有代码风格与惯例
