# Shape(塑形)

目标:把一个欠定的想法变成**可以开始建造的最小决策集**,而不是一份大而全的 PRD。在获得第一次真实反馈(用户体验到运行中的产品)之前,详尽规格的边际价值极低、幻觉风险极高——所以塑形只回答四个问题、切出切片,把其余决策推迟到有反馈的时候。

## 流程

### 1. 初始化产品层

```bash
python3 skills/hf-workflow/scripts/hf_gate.py init
```

生成 `product/` 四文件模板(已有文件不覆盖)。

### 2. 结构化访谈

只围绕四个问题,**合并成尽量少的轮次**,不搞 50 连问:

1. **给谁用**:目标用户是具体的谁?(拒绝"所有人";让用户描述一个真实场景里的一个人)
2. **解决什么问题**:现状哪里痛?不用这个 APP 时用户怎么办?
3. **成功长什么样**:第一版做到什么程度算成了?(可观察的信号,如"能完成一次完整的 X")
4. **明确不做什么**:第一版排除什么?(防范围蔓延的唯一手段是把"不做"写下来)

用户答不上来的问题,**给带默认值的选项让用户挑**,而不是开放式追问;用户仍不表态 → 取默认值记入 `assumptions.md`,继续推进。

### 3. 技术栈决策(带观点的默认值)

让非技术用户做技术选型,是把决策推给信息最少的一方。对照预设直接给出推荐:

| 产品形态 | 默认预设 | 默认理由 |
|----------|----------|----------|
| Web 应用(默认) | Next.js/React + SQLite,单仓 | 一栈到底、本地即跑、预览部署成熟 |
| 纯后端 API | Python FastAPI 或 Node,SQLite→Postgres | 上手快、测试生态好 |
| CLI / 工具 | Python 或 Go 单二进制 | 分发简单、stdlib 够用 |
| 静态站 / 展示页 | 静态生成器 + 托管平台 | 零运维 |

规则:用户明确选择 → 记入 `decisions.md`(D-n);未表态 → 用默认并记入 `assumptions.md`(A-n,状态"生效")。团队既有栈、部署约束等真实约束**压倒**默认预设。选一门本地能跑通验证环路(测试 + 启动)的栈——环境基线跑不通的栈再时髦也不选。

### 4. MVP 切割与 backlog

把 MVP 边界切成**垂直切片**写入 `backlog.md`:

- 每片端到端可演示(UI→逻辑→存储打通一条真实路径),不按技术分层切("先把数据库都建好"不是切片)。
- `S-1` 固定为行走骨架(见 `hf-skeleton`),之后按"用户价值 ÷ 体量"排序。
- 每片写**演示判据**:交付时用户能看到/做到什么。写不出演示判据的切片说明还没想清楚,拆小或推迟。
- 第一批 3~6 片足够;backlog 是活文档,每次 ship 后按反馈重排。

### 5. 确认与推进

向用户呈现一屏摘要:一句话想法、目标用户、MVP 边界、不做清单、技术栈(标注哪些是默认假设)、前几个切片。用户确认后在 `product.md` 写 `- 用户确认: <日期>`;auto 模式可写 `auto-approved <日期>`,但前提是所有替用户做的选择已入台账。然后:

```bash
python3 skills/hf-workflow/scripts/hf_gate.py check --product
```

PASS 后进入 S-1(读 `hf-skeleton`),RESULT 行记入首个特性的 progress.md。

## 假设台账纪律

- 遇到欠定点的标准动作:**提出带默认值的选项 → 记一条 `A-<n> <日期> [生效] <假设> — 默认理由: <一句话>` → 继续**。禁止静默填补,也禁止因等待答复而停摆。
- 用户确认某假设 → 状态改"已确认",内容迁入 `decisions.md`;用户推翻 → 状态改"已推翻",评估波及面,回受影响的阶段受控返工。
- 台账是给用户随时翻看的:每次向用户汇报时,新增假设要点名提示。

## 红线

- 访谈变成问卷轰炸,或反过来一个问题都不问就开写
- 产出几十页 PRD、用户画像、竞品分析(塑形只装最小决策集)
- 为填模板发明用户数据、市场数字、性能指标
- 把未经确认的假设写成 decisions.md 里的已确认决策
- backlog 按技术分层切片,或切片没有演示判据
- 跳过 S-1 行走骨架直接做"最有意思的功能"
