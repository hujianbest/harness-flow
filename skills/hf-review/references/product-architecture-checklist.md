# 产品架构评审检查清单

适用于 `product/architecture.md`（系统地图，非特性实现设计）。

## 硬项

- [ ] 架构特征 3~5 个，各带可检验的质量属性场景（刺激→响应→度量）；原则与风格能回应这些特征（特征先于风格）
- [ ] 依赖方向写清，无循环暗示
- [ ] 模块/上下文为 3–7 个，职责不重叠到「什么都管」；每个写明封住的易变性，非纯技术层切蛋糕
- [ ] 开发视图能回答「新代码放哪 / 测试放哪」，且答案唯一显然
- [ ] 关键场景可当作垂直切片判据，并标注各自验证的架构特征
- [ ] 演进节含已识别易变性的演进路径与量化复核触发；依赖硬规则与关键特征配有适应度函数（校验方式 + 频率）
- [ ] 难逆转点进 ADR，而非堆在正文
- [ ] 未把特性级接口/字段细节塞进产品架构（有则拒绝）

## 决策质量

- [ ] 原则与风格可指导后续特性架构增量注解
- [ ] 每条结构决策可追溯到某个架构特征或已识别易变性（无「为优雅而优雅」）
- [ ] 冲突特征的取舍写明，敏感点进 ADR；最可能致返工的风险有早期验证安排
- [ ] 演进内容只含路径与触发，未预写未来设计细节；无过度设计：不为未确认未来引入抽象层
- [ ] 多上下文时有 `CONTEXT-MAP.md` 或等价索引

## 体量

- [ ] 正文 ≤120 行量级，是地图不是论文
