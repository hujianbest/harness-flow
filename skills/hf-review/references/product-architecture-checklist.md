# 产品架构评审检查清单

适用于 `product/architecture.md`（系统地图，非特性实现设计）。

## 硬项

- [ ] 依赖方向写清，无循环暗示
- [ ] 模块/上下文为 3–7 个，职责不重叠到「什么都管」
- [ ] 开发视图能回答「新代码放哪 / 测试放哪」
- [ ] 关键场景可当作垂直切片判据
- [ ] 难逆转点进 ADR，而非堆在正文
- [ ] 未把特性级接口/字段细节塞进产品架构（有则拒绝）

## 决策质量

- [ ] 原则与风格可指导后续特性架构增量注解
- [ ] 多上下文时有 `CONTEXT-MAP.md` 或等价索引
- [ ] 无过度设计：不为未确认未来引入抽象层

## 体量

- [ ] 正文 ≤120 行量级，是地图不是论文
