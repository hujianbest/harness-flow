# 代码异味基线

Fowler《重构》第 3 章。Standards 轴始终检查下列异味，即使仓库没有编码规范文档。

- **仓库规则优先。** 已记录的仓库标准始终优先；若仓库标准认可某种会被基线标记的做法，则不报告该异味。
- **始终需要判断。** 每种异味都是启发式，不是硬性违规；跳过工具已强制检查的内容。

每种异味按「是什么 → 如何修复」：

- **神秘命名（Mysterious Name）**——名称未揭示作用。→ 重命名；无法如实命名则设计含混。
- **重复代码（Duplicated Code）**——同一逻辑形态出现在多处差异块。→ 提取共享形态。
- **依恋情结（Feature Envy）**——方法访问另一对象的数据多于自身。→ 把方法移到数据所在处。
- **数据泥团（Data Clumps）**——同一组字段总是一起传递。→ 封装成类型。
- **基本类型偏执（Primitive Obsession）**——用基本类型代替领域概念。→ 建立小型类型。
- **重复的条件分支（Repeated Switches）**——同一类型的 switch/if 反复出现。→ 多态或共享映射。
- **霰弹式修改（Shotgun Surgery）**——一处逻辑变更迫使许多文件改动。→ 把共同变化集中到一个模块。
- **发散式变化（Divergent Change）**——一个模块因多个无关原因被改。→ 拆分，使每个模块只因一个原因变化。
- **夸夸其谈的通用性（Speculative Generality）**——为规格中不存在的需求加抽象。→ 删除，直到出现真实需求。
- **消息链（Message Chains）**——长串 `a.b().c().d()`。→ 把遍历藏进第一个对象的方法。
- **中间人（Middle Man）**——主要只负责继续委托。→ 移除，直接调用真实目标。
- **被拒绝的遗赠（Refused Bequest）**——子类忽略大部分继承内容。→ 改用组合。
