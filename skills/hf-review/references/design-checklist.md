# 设计/架构评审检查清单

适用于特性 `architecture.md`(对照已批准的 `spec.md`)。有 UI 时并入 `hf-ui-design` 检查项。

## 产品对齐

- [ ] 存在 `product/architecture.md` 时，正文含对齐声明（`## 对齐产品架构` 或引用该路径）
- [ ] 本片落点模块/场景与产品地图一致；越界有显式标注与 ADR/假设
- [ ] 未复述产品架构全文（应为增量注解）

## 需求覆盖

- [ ] `spec.md` 中每条关键能力都能在模块/流程中找到落点
- [ ] 未引入 `spec.md` 之外的新能力（如有，则须回写 `spec.md` 或标为范围外事项）
- [ ] 测试缝与 `architecture.md` 中的缝一致

## 决策质量

- [ ] 模块边界清晰(职责一句话);优先深模块、小接口
- [ ] 新缝确有必要且位于最高可测点；能复用旧缝却新开 → 发现项
- [ ] 偏离 CONTEXT/产品架构/既有结构有理由,并入 ADR 或假设台账
- [ ] 无过度设计:不为未确认未来引入抽象层

## 可实现性

- [ ] 关键流程可被 `hf-to-tickets` 拆成垂直切片
- [ ] 失败模式有对策
- [ ] 正文 ≤80 行量级,细节未假装成已实现
