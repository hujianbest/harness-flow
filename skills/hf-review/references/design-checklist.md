# 设计/架构评审 Checklist

适用于特性 `architecture.md`(对照已批准的 `spec.md`)。加载的 `ext-*` 追加项一并检查。

## 需求覆盖

- [ ] spec 中每条关键能力能在模块/流程中找到落点
- [ ] 未引入 spec 之外的新能力(有则须回写 spec 或标出 of scope)
- [ ] Testing 缝与 architecture 中的缝一致

## 决策质量

- [ ] 模块边界清晰(职责一句话);优先深模块、小接口
- [ ] 新缝有必要且取在最高可测点;能复用旧缝却新开 → finding
- [ ] 偏离 CONTEXT/既有结构有理由,并入 ADR 或假设台账
- [ ] 无过度设计:不为未确认未来引入抽象层

## 可实现性

- [ ] 关键流程可被 `hf-to-tickets` 拆成垂直切片
- [ ] 失败模式有对策
- [ ] 正文 ≤80 行量级,细节未假装成已实现
