# 设计评审 Checklist

适用于 `design.md`(对照已批准的 spec.md),或 `plan.md` 的设计+任务章节(对照其需求章节)。加载的 `ext-*` 扩展若声明了本层追加检查项,一并检查。

## 需求覆盖

- [ ] 每条 FR/NFR 都能在设计中找到落点;任务清单"覆盖"标注穷尽全部 FR/NFR
- [ ] 设计没有引入需求之外的新需求或新能力
- [ ] 每条 NFR 有明确的满足机制与验证方式
- [ ] frame 的风险档位与实际改动面相符;定低即为严重 finding(升档重走)

## 决策质量

- [ ] 真实决策点列出 ≥2 个方案并有可检验的取舍分析;没有表演性对比,也没有"直接选定"
- [ ] 无过度设计:没有为未确认的未来需求引入的抽象层、接口、配置项
- [ ] 与现有代码的关系明确:复用什么、新增什么;偏离既有模式的地方有理由
- [ ] 有 `product/architecture.md` 时:设计落在其模块边界与横切约定之内,或显式标注了"架构影响"

## 可实现性

- [ ] 接口与数据契约具体到实现阶段不需要再发明(签名、结构、错误模型)
- [ ] 关键路径的失败模式有对策
- [ ] 测试策略可执行:分层明确、有运行命令、指明必须覆盖的边界

## 任务清单

- [ ] 格式机器可读(`- [ ] T-<n> ...`),每项有可判定的完成判据
- [ ] 每个任务一次 TDD 循环内可完成;按依赖排序,T-1 打通最薄端到端路径
- [ ] 环境基线失败且未修复时,T-1 是"恢复基线"
- [ ] 没有"研究一下""优化性能"这类无判据任务
