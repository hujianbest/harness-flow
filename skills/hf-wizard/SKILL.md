# 向导

**向导**是一个 bash 脚本，逐步引导人工完成手动操作流程；这些操作亲手执行很繁琐，每次向 AI 重新解释也很繁琐。它会打开每个 URL，准确说明要点击和复制什么，捕获值，将其写入应在的位置（`.env`、GitHub 密钥），在每个阶段进行确认，并显示剩余阶段数。它可以配置第三方服务、执行一次性迁移，或将项目从一种状态转移到另一种状态。

[template.sh](template.sh) 已经解决了令人愉悦的用户体验——逐阶段进度、确认门禁、跨平台 URL 打开（包括 WSL）、隐藏式密钥输入、幂等的 `.env` 更新插入、`gh secret`/`gh variable` 写入以及结束摘要。**你的工作只是界定流程范围并编写各阶段。**每个向导中 `STAGES` 标记上方的库都完全相同；保持这种一致性正是目的——绝不要手动编辑它。

向导默认是临时的——为单次运行而构建，保存到临时路径或 `scripts/` 路径，任务完成后删除。仅当用户希望仓库中保留可重复执行的设置路径时才提交它。

## 流程

### 1. 界定流程范围

梳理人工必须执行的每个手动步骤，以及过程中捕获的每个值。先读取仓库——不要毫无准备地提问：

- 对于设置：读取 `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置和 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是向导必须生成的值）。
- 对于迁移或转换：明确当前状态、目标状态以及两者之间的不可逆操作。

然后向用户展示有序的阶段列表以及每个阶段产生的值，并进行确认——他们可以添加、删除或重新排序。

**完成条件：**每个阶段均按顺序命名，并且对于每个捕获的值，你都知道：(a) 人工从哪里获取它，(b) 它写入哪里（`.env`、GitHub 密钥、两者，或不写入任何位置——有些阶段只是操作），以及 (c) 它是密钥（隐藏输入）还是公开值。

### 2. 绘制每个阶段的操作路径

为每个阶段写出人工遵循的精确路径：打开哪个 URL、在那里做什么、值显示在哪里、填入哪个变量——例如“仪表板 → 开发者 → API 密钥 → 显示测试密钥 → 复制”。如果你确实不知道当前 UI 或确切命令，请明确说明并询问用户或查阅文档——绝不要编造可能不存在的步骤。

**完成条件：**每个阶段都有陌生人也能遵循的具体说明。

### 3. 编写向导

将 `template.sh` 复制到目标路径。按依赖顺序，用每个步骤一个 `stage` 替换示例阶段。使用库辅助函数——`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`——并将 `TOTAL_STAGES` 设置为所编写的阶段数。

保持模板设定的标准：在请求值之前打开 URL，对任何密钥使用 `ask_secret`，对每个持久化值使用 `write_env`，仅对 CI 实际需要的值使用 `set_secret`，并在任何不可逆操作前使用 `confirm`。每个 `stage` 都会清屏，只显示当前步骤——每个阶段只聚焦一项任务，避免人工所需内容滚出屏幕。不要改动标记上方的库。

### 4. 验证并交付

- `bash -n <script>`；如果可用，运行 `shellcheck`。
- `chmod +x <script>`。
- 不要亲自端到端运行——它会打开浏览器并阻塞等待人工输入。改为静态追踪：第 1 步中的每个值都已捕获并落到第 1 步指定的位置，且每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用完全匹配。
- 告诉用户如何运行。如果这是可重复执行的设置路径，请提交它并在 README 中添加链接，让下一个人运行脚本，而不是询问 AI。
