# Frame(定格)

目标:回答四个问题——**要做什么**(一句话意图与范围)、**做完留不留**(模式)、**多危险**(风险档位)、**这个项目我能验证吗**(环境基线)。frame 是唯一没有独立评审的阶段,所以它只允许装低成本、可被后续评审推翻的决定;拿不准的一律往高档靠。

**入口分流**:用户带着从零开始的产品想法、且项目没有 `product/` 产品层 → 先走 `hf-shape`(产品定义)与 `hf-architect`(架构与拆解);产品层已就绪 → 本切片从 `hf_gate.py next` 取,frame 里记录对应切片编号。

## 流程

### 1. 建目录与定意图

读用户请求;有 `product/architecture.md` 时**先读它**定位受影响的模块与流程,再只读相关代码,不做全库扫描(没有地图的存量项目按需探索;需要反复交付时建议按 `hf-architect` 补一份地图)。取 `features/` 下一个编号创建 `features/<NNN>-<slug>/` 与 progress.md(格式见 `hf-workflow`)。把意图压缩成一句话;**会改变范围或验收标准的阻塞性未知项,合并成尽量少的轮次一次问清**;可合理假设的次要项写入 frame.md 假设区(有产品层时同步记入 `product/assumptions.md`),标注"如不对请指出"。

### 2. 定模式

- **建造**(默认):产物会被保留进产品 → 全纪律。
- **探索**:目的是验证一个方向/交互/技术可行性,产物即弃 → 链路 frame → build → close,低仪式。判据:做完后代码会被扔掉重写才算探索;"先做出来看看,行就留下"不是探索,是建造。探索仅限风险档位 1——碰数据/安全/公共接口的工作不允许探索模式(gate 会拦截)。

### 3. 定风险档位

对照判据,从高往低判,任一命中即入该档:

| 档位 | 判据(任一命中) |
|------|----------------|
| 3 高危 | 数据迁移/删除;认证、授权、支付等安全面;跨 ≥3 模块的结构调整;破坏公共 API 或存储格式;不可逆操作 |
| 2 标准 | 新功能、行为变更、非平凡缺陷修复;**默认档** |
| 1 微改 | 单点小改(典型 ≤2 个文件),行为边界清晰,可逆,不碰数据/安全/公共接口 |

档位理由必须落盘,可被冷读检验。档位由后续评审复核:档位 2/3 在 plan 层评审复核,档位 1 在代码评审复核(diff 与档位不符即严重 finding,升档重走)。

### 4. 定用户可感知

改动交付后用户能直接看到/操作到(界面、交互、输出格式、CLI 行为)→ `是`,ship 前 gate 会要求 demo 验收与落盘的用户验收;纯内部改动(重构、依赖升级、内部性能)→ `否`。拿不准 → `是`(只会多一道演示,不会漏验收)。

### 5. 建环境基线

确认项目可验证——真实运行项目的全量测试(或构建)一次:

- 找不到测试命令时,读 README、CI 配置、包管理脚本(package.json / Makefile / pyproject 等)。
- **基线失败**(环境坏 / 既有测试红):恢复可验证性优先——要么当场修好基线再继续,要么把"恢复基线"列为计划的 T-1。基线可运行之前,后续任何 TDD 都不成立。
- **全新项目**:基线 = 搭起最小可运行的测试骨架并跑通一个空测试。
- **探索模式**:不要求基线(原型不承诺可验证性),但仍建议确认。

### 6. 写 frame.md 并推进

```markdown
# <特性名> Frame

- 日期: YYYY-MM-DD
- 意图: <一句话:为谁改什么、改到什么程度算完成>
- 切片: S-<n> | 无
- 范围外: <明确不做的;无则写"无">
- 模式: 探索|建造
- 风险档位: 1|2|3
- 档位理由: <对照判据,可被冷读检验>
- 用户可感知: 是|否
- 环境基线: <跑了什么命令、是否通过;失败时的恢复计划;探索模式免除>
- 假设: <未经确认的合理假设;无则写"无">
```

- 建造 + 档位 ≥2 → `gate check --to plan`,PASS 后进 `hf-plan`。
- 建造 + 档位 1、或探索 → `gate check --to build`,PASS 后直接进 `hf-build`。
- RESULT 行记入 progress.md 的"门禁输出"。

## 红线

- 跳过基线确认直接进 plan/build("这个项目肯定能跑"不算证据)
- 为省流程把明显碰安全/数据/公共接口的改动定为档位 1 或 2,或伪装成"探索"
- 档位理由写成"感觉不大"这类不可检验的句子
- 在 frame 里写接口签名、表结构、框架选型等设计内容(那是 plan 的事;栈选型与模块边界是 architect 的事)
- 阻塞性未知项不问清,靠猜测开工
- 有产品层却不从 backlog 取切片、不记切片编号(切片账目会失真)
